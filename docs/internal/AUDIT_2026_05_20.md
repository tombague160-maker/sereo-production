## 🔴 P0 — Critique (à corriger sous 7 jours)

### S1. XSS potentiel dans `inlineMarkdown` (modal "Quoi de neuf")
- **Fichier** : `public/js/app.js:3863-3871`
- **Risque** : le texte d'un lien Markdown (`[texte](url)`) est inséré dans `innerHTML` sans `escapeHtml()`. Si une release note GitHub future contient `[<img src=x onerror=alert(1)>](url)`, exécution de JS arbitraire.
- **Sévérité** : Medium en pratique (notes contrôlées par toi), mais facile à fixer.
- **Fix** : remplacer la regex `.replace(...)` par un callback qui escape le `$1` (texte) :
  ```js
  .replace(/\[([^\]]+)\]\((https?:\/\/[^)\s]+|#[^)\s]+)\)/g,
    (m, text, url) => `<a href="${escapeAttribute(url)}" target="_blank" rel="noopener noreferrer">${escapeHtml(text)}</a>`)
  ```

### S2. Secret HMAC faible si `SEREO_AUTH_SESSION_SECRET` non défini
- **Fichier** : `server.js:118-119`
- **Risque** : si la var d'env est vide, fallback sur `AUTH_REALM` (`"Sereo"` par défaut) + `AUTH_PASSWORD`. Sur ton OMV, `AUTH_PASSWORD = "OERES"` → secret = `"Sereo|OERES"` = brute-force trivial pour forger un cookie de session.
- **Fix immédiat** : ajoute dans ton Tom.yml :
  ```yaml
  environment:
    SEREO_AUTH_SESSION_SECRET: "une-string-aleatoire-de-32-caracteres-minimum-ici"
  ```
- **Fix code** : générer un secret random fort si vide :
  ```js
  const AUTH_SESSION_SECRET_BASE = cleanEnv(process.env.SEREO_AUTH_SESSION_SECRET)
    || crypto.randomBytes(32).toString("base64");
  ```
  ⚠️ Effet de bord : tous les cookies de session deviennent invalides au redémarrage (acceptable).

### A1. README.md absent
- **Risque** : nouveau dev ou IA qui regarde le repo n'a aucun setup. Pas de capture, pas de "Comment lancer localement".
- **Fix** : créer un README.md de ~80 lignes avec : description app, prérequis (Node 24+), `npm install` / `npm start`, env vars minimales, URL d'accès local, capture d'une page.

### U1. Pas de spinner pendant les `apiFetch()` longs
- **Fichier** : `public/js/app.js:498, 541-556`
- **Risque** : UI gèle silencieusement lors d'un import 10s, l'utilisateur croit que c'est cassé et reclique. Risque de double-import.
- **Fix** : ajouter overlay loader sur `runAction` quand `> 500ms`, + `aria-busy="true"` sur `#syncStatus`.

### U2. Contrast WCAG fail en dark mode (orange)
- **Fichier** : `public/css/style.css` (variables dark)
- **Mesure** : `--color-pastel-orange-strong: #f08864` sur fond `#0d1518` = ratio **4.2:1** (AA fail, exige 4.5:1).
- **Fix** : remonter à `#ed9d72` (5.1:1) ou `#f0a07a` (5.5:1) en dark mode.

## 🟠 P1 — Majeur (à planifier sous 30 jours)

### S3. Rate limit bypass via `X-Forwarded-For` mal contrôlé
- **Fichier** : `server.js:216` (`app.set("trust proxy", 1)`)
- **Risque** : si SWAG ne strippe pas `X-Forwarded-For`, un attacker peut forger des IPs pour bypass le lockout `/login`.
- **Fix** : vérifier ta config SWAG (probablement OK car SWAG strippe par défaut). Sinon, utiliser un `session_id` cookie pour le rate limit au lieu de l'IP seule.

### S4. Upload .xlsx : check par extension seulement
- **Fichier** : `server.js:193-209`
- **Risque** : un fichier .exe renommé `.xlsx` passe le filtre. Pas exploitable en l'état (read-excel-file rejette les non-zip), mais belt-and-suspenders.
- **Fix** : vérifier le magic number ZIP (`50 4B 03 04`) au début du fichier avant parsing.

### P1. `syncWorkflow()` appelé dans chaque `readDb()`
- **Fichier** : `server.js:1310-1348` + `2259-2308`
- **Impact** : un seul GET `/api/clients` déclenche normalizeDb → syncWorkflow → reconstruction complète des routes/orders. ~50-100ms par requête, multiplié par les renders frontend qui font 3-5 fetches consécutifs.
- **Fix** : déplacer `syncWorkflow()` dans `writeDb()` uniquement. `readDb` doit être pur (juste lire SQLite).

### P2. Indexes SQLite manquants
- **Fichier** : `storage/sqliteStore.js`
- **Manquent** : `commandes(statut)`, `commandes(date_livraison)`. Ces colonnes sont filtrées partout dans le code.
- **Fix** :
  ```sql
  CREATE INDEX IF NOT EXISTS idx_commandes_statut ON commandes(statut);
  CREATE INDEX IF NOT EXISTS idx_commandes_date_livraison ON commandes(date_livraison);
  ```

### P3. N+1 dans `renderPreparation`
- **Fichier** : `public/js/app.js` lignes 642, 668-670
- **Impact** : `orders.filter(o => o.status === "X")` appelé 4 fois consécutives sur le même array. À 500 commandes = 2000 comparaisons pour calculer les 4 stats.
- **Fix** : pré-calculer un Map `{statut: count}` en 1 passe au début de la fonction, réutiliser.

### A2. Magic strings non centralisées
- **Risque** : `"en_preparation"` apparaît 30x hardcodé, `"livre"` 25x, `"pret_livraison"` 18x. Une typo silencieuse (`"livre"` vs `"livrée"`) crée des bugs invisibles.
- **Fix** : extraire `src/constants.js` avec enum :
  ```js
  const ORDER_STATUS = Object.freeze({
    IMPORTED: "importe", TO_CHECK: "stock_a_verifier",
    IN_PREP: "en_preparation", READY: "pret_livraison",
    IN_DELIVERY: "en_livraison", DELIVERED: "livre"
  });
  ```

### U3. Modal ne piège pas le focus (Tab leaks out)
- **Fichier** : `public/js/app.js:443-470` (`openMoreMenu`, `openBdcDetail`)
- **Fix** : `focus-trap` minimal — mémoriser premier/dernier focusable du modal, intercepter `Shift+Tab` sur premier et `Tab` sur dernier pour wrap.

### U4. Cartes cliquables sans Enter/Space handler
- **Fichier** : `public/js/app.js` cards `[data-action="open-bdc-detail"]` ont `role="button" tabindex="0"` mais seul `click` est géré.
- **Fix** : ajouter `keydown` handler global qui catch Enter/Space sur ces éléments.

### T1. Aucun test frontend (`app.js`)
- **Risque** : 3889 lignes de code vanilla JS jamais validé automatiquement. Une régression UI passe en prod sans alerte.
- **Fix** : ajouter Playwright (E2E) avec 5-10 scénarios golden path : login → import → préparation → tournée → livraison. ~2 jours de setup + écriture.

### T2. Tests de stress manquants
- **Manque** : Excel 5000+ lignes, DB corrompue, mémoire saturée.
- **Fix** : générer 1 fichier Excel 10000 lignes en mémoire dans un test, mesurer durée import < 30s. Catch les régressions perf futures.

### D1. CLAUDE.md pas à jour v1.12.0
- **Manque** : section archivage Excel imports, endpoints `/api/imports/archives*`, `/api/orders/purge`.
- **Fix** : 20 lignes à ajouter dans la section "Modèle ERP".
