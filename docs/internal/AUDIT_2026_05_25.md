## 🔴 P0 — Bugs métier à corriger sous 7 jours

### B1. Double-comptage du stock nécessaire (SQL bug logique)

**Fichier** : `server.js:2048-2056` (`calculateNeededStock`)

**Problème** : `calculateReservedStock` compte les commandes aux statuts `en_preparation`, `preparation_terminee`, `pret_livraison`, `en_livraison`. MAIS `calculateNeededStock` recompte AUSSI `en_preparation` et `pret_livraison` → **double-comptage**.

**Conséquence métier** : tes recommandations "à commander" sont **gonflées artificiellement**. Une commande en préparation apparaît dans `quantityReserved` **ET** dans `quantityNeeded` → le système croit qu'il faut deux fois plus de stock.

**Fix** :
```javascript
function calculateNeededStock(db, product) {
  return db.commandes.reduce((total, order) => {
    // Exclure les statuts déjà comptés dans calculateReservedStock
    if (!["importe", "stock_a_verifier"].includes(order.status)) return total;
    return total + getQuantityForProductInOrder(product, order);
  }, 0);
}
```

**Effort** : 15 min code + 1 test régression.

### B2. Backtrack `pret_livraison → en_preparation` autorisé (workflow)

**Fichier** : `server.js:189` (`ORDER_STATUS_TRANSITIONS`)

**Problème** : la state machine autorise une commande **prête à livrer** à revenir en **préparation**. Pas censé exister métier (une commande validée prête à partir ne doit pas reculer).

**Fix** : retirer `"en_preparation"` de la liste des transitions valides depuis `"pret_livraison"`.

**Risque régression** : faible (cas rare, à vérifier que personne ne s'en servait pour corriger un oubli de prépa).

**Effort** : 5 min.

### B3. Recovery SQLite corruption absent (risque crash serveur)

**Fichier** : `server.js:1305` (`readDb`) + `storage/sqliteStore.js`

**Problème** : si la base SQLite est corrompue (coupure courant pendant écriture), `getSqliteStore().readDb()` throw sans catch → **crash serveur**, `/login` devient inaccessible.

**Fix** : wrapper try/catch dans `readDb()` avec auto-restore depuis le backup le plus récent + log alerte.

**Effort** : ~1h (catch + scan backups + restore + healDatabase).

### B4. Produit supprimé entre check stock et réservation = stock perdu silencieusement

**Fichier** : `server.js:2566-2582` (`reserveStockForOrder`)

**Problème** : si un produit est supprimé entre `analyzeOrderStock` et `reserveStockForOrder`, la boucle continue silencieusement → réservation partielle, mais `setOrderStatus("en_preparation")` réussit quand même. L'opérateur croit que la commande est en prépa mais une ligne a sauté.

**Fix** : `throw badRequest("Produit X introuvable")` au lieu de `return` silencieux.

**Effort** : 15 min + 1 test.

## 🟡 P2 — Polish & dette (backlog)

### Métier

- **Recherche stock** : highlight des résultats matchés (UX)
- **Quick edit inline stock** : input direct au lieu de boutons +1/+5 répétés
- **Vue tableau dense stock** : 30 produits visibles d'un coup
- **Sélection multi Bons de commande** : actions groupées
- **Prévisualisation import Excel** : voir le diff avant de committer
- **Drag & drop** dans Préparation kanban (4 colonnes) — overkill probable
- **Stop status "en_attente"** : pause dans la tournée sans clore le client
- **Bons sans clients orphelins** : nettoyage périodique
- **Audit log par utilisateur** : `createdBy` toujours "local" actuellement

### Tech

- **Cache in-memory DB** : éviter `readDb()` à chaque requête
- **UPSERT par diff** : éviter wipe-and-replace SQLite à chaque writeDb
- **Bundle minification** : `app.js` 144 KB → ~40 KB gzip
- **Virtualisation listes** > 5000 items (`renderCommandesLivrees`)
- **Suppression code mort JSON** dans sqliteStore.js (~100 LOC legacy)
- **Index `lignes_commande(commande_id)`** (FK manquant)
- **Validation centralisée Zod** (au lieu de checks manuels dispersés)
- **CSP `upgrade-insecure-requests`** + HSTS si HTTPS
- **API versioning** `/api/v1/` pour future breaking change

### Design system

- **Échelle spacing cohérente** : 4/8/12/16/24/32 (au lieu de valeurs arbitraires)
- **Échelle typo** : xs/sm/base/lg/xl/2xl avec line-height harmonisé
- **Breakpoints standardisés** : 640 / 1024 / 1400 (au lieu de 380/480/520/720/820/1100)
- **Composants `.button--variant`** au lieu de `.context .button` (lourde spécificité)
- **Suppression dead CSS** : `.nav-badge`, `.workflow-card`, etc.

### A11y

- **Touch targets** 44×44 px partout (déjà fait sur les filtres, à étendre)
- **`aria-hidden="true"`** systématique sur SVG décoratifs
- **Mode "haute densité"** : option pour réduire paddings de 30%
